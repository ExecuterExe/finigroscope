# Экосистема: ФинИгроСкоп + Генератор игр

Два самостоятельных сервиса в одном репозитории. У каждого свой каталог, своя
точка входа, свой `.env` и свой `.gitignore`. Общее — только `deploy/` и этот
файл: в один процесс они не сливаются и зависимостей друг у друга не имеют.

```
finigroskop/   ФинИгроСкоп — разбор и доработка настольной игры по документу.
               Flask 3 + SQLAlchemy + SQLite, порт 5000.
generator/     Генератор игр — опросник, из ответов собирает варианты игрового
               цикла. Только стандартная библиотека Python, порт 8000.
deploy/        systemd-юниты и конфиг nginx для VPS.
docs/          документы уровня экосистемы.
```

## Запуск

**Каждый сервис запускается своим `app.py`.** Оба считают пути от собственного
файла, поэтому запускать можно и из корня:

```bash
python finigroskop/app.py
```

```bash
python generator/app.py
```

Оба перезапускаются сами при правке кода: у ФинИгроСкопа это делает Flask, у
генератора — свой сторож (`generator/reloader.py`, выключается
`GENERATOR_AUTORELOAD=0`). Страницу генератора браузер тоже не кеширует, так что
обычного обновления достаточно — `Ctrl+F5` не нужен.

Открывать: ФинИгроСкоп — http://localhost:5000, генератор — http://localhost:8000.
В шапке каждого есть кнопка перехода во второй; адреса берутся из окружения
(`GENERATOR_URL` и `FINIGROSKOP_URL`), а не зашиты в разметку — на сервере они
другие.

Настройки — по одному `.env` на сервис, из соответствующего `.env.example`.
Общего `.env` в корне быть не должно, см. «Грабли» ниже.

Зависимости:

```bash
pip install -r finigroskop/requirements.txt
```

Генератору в рантайме зависимости не нужны. Для его тестов:

```bash
pip install -r generator/requirements-dev.txt
```

## Проверки

**Запускать строго из каталога своего сервиса.** Тесты ФинИгроСкопа начинаются с
`sys.path.insert(0, ".")` и рассчитывают на текущий каталог проекта; из корня
экосистемы `import app` не найдётся, а при неудачном стечении найдётся `config`
от генератора.

```bash
cd finigroskop && python tests/jobs_check.py
```

Наборы ФинИгроСкопа (каждый заканчивается строкой `ВСЁ ОК (N проверок)`):
`jobs_check`, `mirror_flow_check`, `extractor_v3_check`, `gate2_flow_check`,
`spec_accept_flow_check`, `simulationist_v6_check`, `stats_evaluator_check`,
`diagnost_check`, `redesigner_check`, `lens_evaluator_check`,
`lens_module_check`, `synthesizer_check`, `llm_providers_check`,
`llm_settings_flow_check`.
У прогона тестов своя база (`instance/finigroskop-test.db`) и своя папка
загрузок — рабочие данные они не трогают.

Генератор:

```bash
cd generator && python -m pytest tests -q
```

Связь с моделью у генератора проверяется отдельно — `python llm.py` из
`generator/` (нужен настоящий ключ в `generator/.env`).

## Что сервисы уже делают вместе

Кроме кнопок перехода, между сервисами есть одна работающая связь по данным:
**оценка модуля игры по линзам Шелла.**

Генератор собирает игру по частям (механики → сюжет → особенности → компоненты →
правила). Каждый готовый модуль проходит своего агента-аудитора по чек-листу, и
если критичных замечаний нет — уезжает в ФинИгроСкоп на качественную оценку.
Обратно приходит балл от 0 до 10 с тремя знаками (`7.412`) и разбор по
категориям.

```
генератор: агент модуля → аудитор → [нет critical] → HTTP →
    ФинИгроСкоп: /api/lenses/module → очередь → оценщик по линзам → балл
```

Владелец линз — ФинИгроСкоп: 47 линз, веса категорий, промпт и валидатор лежат
только у него (`finigroskop/review/lens_module.py`). У генератора — тонкий клиент
(`generator/agents/lens_review.py`). Копии агента в двух сервисах быть не должно:
это две шкалы Шелла с одинаковым названием, которые разойдутся со второй правки,
а сравнивать баллы между сервисами придётся обязательно.

Две вещи в этом балле важнее самого числа:

- **К модулю применимы не все категории.** Модуль механик не содержит ни сюжета,
  ни количества компонентов. Область применимости объявлена таблицей
  (`finigroskop/review/lens_scope.py`), и всё, что вне её, у модели не
  спрашивается вовсе.
- **Рядом с баллом всегда идёт доля покрытого веса.** Категории в N/A выпадают из
  взвешенного среднего целиком, поэтому 8.4 за модуль механик и 8.4 за игру
  считаются по разному числу категорий. Формулой это не исправить — только
  показать, и страница генератора показывает это полосой покрытия.

Настройка: `LENS_API_URL` и `LENS_API_TOKEN` в `generator/.env`, тот же
`LENS_API_TOKEN` в `finigroskop/.env`. Эндпоинт тратит деньги на модель, поэтому
без токена работает только на сервере разработки — на боевом отвечает 403.

## Грабли, на которые уже наступали

**Один `.env` на оба сервиса — нельзя.** Имена переменных совпадают, а смысл
разный: у ФинИгроСкопа `LLM_PROVIDER` — один из девяти вендоров, у генератора
принимается только `openrouter`; `LLM_TIMEOUT` — 25 с против 60 с; модель у
одного `OPENROUTER_MODEL`, у другого `OPENROUTER_MODEL_PRO/_FLASH/_REASONING`.
Общий файл молча выдаст каждому чужие значения.

**Не добавлять оба каталога в `sys.path` одновременно.** У обоих проектов есть
модуль верхнего уровня `config`, и это разные модули: генератор делает
`from config import config` (объект), у ФинИгроСкопа такого объекта нет. Победит
тот, кто окажется в `sys.path` первым. Пока каждый сервис запускается своим
`app.py`, всё в порядке: Python сам кладёт в `sys.path[0]` каталог запускаемого
скрипта. По той же причине в `finigroskop/alembic.ini` стоит
`prepend_sys_path = %(here)s`, а не `.`.

**`FINIGROSKOP_RESET` на сервере не задавать.** Переменная разрешает стереть
хранилище при старте; в разработке её включает сам `python app.py`.

**`.env` ни одного из сервисов не коммитить.** В `generator/.env` лежит рабочий
ключ OpenRouter. Проверка — обе строки должны что-то вывести:

```bash
git check-ignore -v finigroskop/.env generator/.env
```
